The four false signals, because the pattern matters more than any one of them:

1. A "zero warnings" claim read a **filtered pipeline summary** instead of the
   build log, with a grep that could not have matched the warnings anyway.
2. The circuit breaker's own 22 tests passed while the **full suite failed 12**

3. `testSignOutClearsTokenWithoutNetwork` asserted the **absence of a security

4. A localization run reported **552 tests passing** when the 8 new tests were

The habit that caught all four: establish your own baseline, then be suspicious
when a number does not move.

### Findings inside those, worth not rediscovering

**`/api/telemetry` cannot carry a MetricKit payload.** `analytics/events.ts`
enforces its privacy invariants by construction: closed enums or a lowercase
token regex, `z.strictObject` so unknown keys are rejected rather than stripped.
A payload is a nested tree of histograms; a binary UUID is uppercase hex. The
schema is not an obstacle to route around, it is the control keeping merchant
names out of analytics. The client now REDUCES each payload on device to a
`device_metrics` event carrying no string property at all.

**Crash data is tamer than it sounds.** `MXCallStackTree.JSONRepresentation`
carries binary image name, binary UUID, text-segment offset, address and sample
count. Unsymbolicated: no function names, no file paths. The genuinely free-form
fields are `terminationReason`, `virtualMemoryRegionInfo` and
`exceptionReason.composedMessage` (Apple's header says it "**may** have
**some** pieces redacted"), and those get dropped client-side.

**The privacy policy was right and the other two documents were stale.** Coiny
does not collect name or email at four layers: no Apple scopes requested,
stripped from the API schema, only `sub` read from Google's token, and the
columns dropped in migration `0054`. While verifying that, the Step 3
consistency invariant turned out to be wrong *when it was written* ("9 entries
matching the 9 rows"; there were 10 of each). The check most likely to catch
drift had drifted, and named a number confidently enough that nobody recounted.

**A String Catalog key with only a non-default localization SHADOWS the Swift
`defaultValue:`.** The first version of #327 would have shipped
`assetClass.checking` as literal on-screen text to every US user, while every
en-GB assertion stayed green. `testEveryLocalizedKeyResolvesRatherThanEchoingItself`
is what fails if it regresses.

**The circuit breaker needs a distinct error type or it sustains its own
outage.** Every caller treats a throw from `fetchWithRetry` as evidence about
vendor health, so a plain `Error` would make them record failures for a vendor
never contacted, feeding the breaker fabricated evidence. Hence
`CircuitOpenError`, `isCircuitOpenError`, and `classifyError` mapping it to
`circuit_open` rather than `unknown`.

## 3. Limitations that remain

**222 `NSLock` noasync warnings** across 30 test files. Pre-existing, identical
at `SWIFT_STRICT_CONCURRENCY: minimal`, unrelated to data isolation. They block
BOTH the eventual `SWIFT_VERSION: 6` flip and extending
`SWIFT_TREAT_WARNINGS_AS_ERRORS` to the test targets, which is the reason CI
stayed green on a build carrying 421 warnings. `CoinbaseViewModelTests` already
uses `lock.withLock`, so there is an in-repo pattern to copy rather than a
convention to invent. Its own PR.

**MetricKit's crash half is declared but not built.** Deliberate: the labels
landed with the metrics half so the privacy trio moved exactly once. The
`MXDiagnosticPayload` subscriber is code-only now, and it needs a NEW endpoint,
not `/api/telemetry`, for the reason in section 1.

**The UI test suite has at least two distinct flakes** and only about one in
eight CI runs executes it, because the `changes` gate only fires on `ios/`
paths. Seen this session: a contrast measurement on `RUNG 4 BUFFER` that passed
on the same commit and same simulator when re-run, and an AX-runner
initialisation timeout. Both are underreported rather than new.

**The runbook and `01-security.md` are substantially stale.** Every `[Agent]`
security item checked was already done: G1.11 (revoke-all-sessions), G1.12
(`.completeFileProtection`), G1.19 (the CI scanner gate), G1.20 (secret-scan
history), G1.25 (`SECURITY.md`). Rows 1.0.11 and 1.2.4 still describe fixed
conditions as FAILS. **Do not work that list top-down without verifying each
row against the code first.**

**Certificate pinning is NOT a gap.** Row 1.12.1 refuses it deliberately, citing
Apple's own "should be avoided" guidance and a total-unrecoverable-failure cost
analysis for a solo founder. That reasoning is better than any case for adding
it. Do not re-open.

## 5. Standing instructions

Unchanged from `handoff-2026-08-23.md` section 8, plus three learned overnight.

- **Check `uptime` before diagnosing any backend test timeout.** A booted
  simulator burns ~200% CPU and drove load average to 566, producing 14 failures
  across five files that no change could explain. `xcrun simctl shutdown all`
  after every iOS run, and never run an iOS build and `test:coverage` together.
- **A test count identical to the baseline means your new tests did not run.**
  `xcodegen generate` after adding a test file, and check the count moved.
- **Do not put process-global resets in `tests/setup.ts`.** Importing `src/`
  there pulls in `config.js`, which snapshots `process.env` at import time
  (`config.ts:407`), before test files set their own env at module scope.
  Reset per file, with a dynamic import inside the hook.
