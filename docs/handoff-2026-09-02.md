## 2. The bug that would have broken the TestFlight run

`ios/project.yml` set `aps-environment: development` for **every**
configuration. TestFlight builds always use production APNs and there is no way
to upload one that does not. A Release build carrying `development` registers a
**sandbox** device token, the production backend sends to
`api.push.apple.com`, and APNs answers **400 BadDeviceToken**.

Push would have been silently dead on every TestFlight build, with no error
visible to the user, the tester, or the server. Push is the mechanism the whole
product runs on.

`backend/src/push/apns.ts` already reasoned about this and states the intended
correspondence: `Release -> production -> production`. The backend half was
correct; the app half made that sentence false.

Fixed with two entitlements files chosen per configuration. **This required
removing XcodeGen's `entitlements:` block**, which writes
`CODE_SIGN_ENTITLEMENTS` into every configuration and silently overrode a
per-config value. The first attempt looked correct and did nothing;
`xcodebuild -showBuildSettings` is what caught it.
`CoinyTests/EntitlementsParityTests.swift` guards the two files against drift
and was proven by flipping the value and confirming exactly one failure.

## 3. The journal trap is now enforced, not documented

A branch cut from `main` added `0066` while `0065` was still open in another
PR. Merged in that order, `0065` would have arrived with an earlier timestamp
and been silently skipped. Caught by hand.

**The trap was already documented in three places** (root `CLAUDE.md`,
`backend/CLAUDE.md`, auto-memory) and nearly happened anyway. In the same
session `branch-guard.sh` blocked commits to `main` and was never violated, not
because it was remembered but because it was impossible.

`bin/check-migration-journal.sh` now runs in `backend-ci.yml` before install
and compares the branch to `origin/main`: new `when` above main's newest, new
`idx` above main's highest, and no edit to an entry already on main.
`backend/tests/migration-journal.test.ts` cannot catch this because it only
ever sees one journal, and both branches were internally monotonic.

**Rule going forward:** when a mistake is expensive and has happened once, ask
what would make it impossible rather than where to write it down.

## 6. Verification notes, because three "green" signals lied

- **A pipe destroys the exit code.** `cmd | tail` reports `tail`'s status,
  always 0, and truncates the summary away. One suite reported green while a
  test was failing.
- **`npx vitest` from the repo root** fetches a different vitest with a broken
  native binding and runs zero tests while exiting non-zero. Run it from
  `backend/`.
- **Never mutate the tree while a suite runs.** A `git stash` mid-run meant
  later files tested different source than earlier ones.
- **Machine load poisons PGlite.** Hook timeouts at load average 238 to 492 in
  files unrelated to the change; all passed in isolation in seconds. Check
  `uptime` before diagnosing.
- **vitest transpiles without typechecking.** New tests passed while `tsc`
  failed on an indexed lookup. Run all three gates, after the last edit.
