## 2. Cybersecurity, error tracking, secure logging

### What is genuinely in place

Verified, not assumed:

- **Log redaction** (#241, #260, G1.21). A 79-entry redact list, `user_id` on
  the request line, `res.url` on completion. Plus the three leaks a redact list
  cannot reach, closed separately.
- **Encryption at rest.** AES-256-GCM envelope with a version byte, key
  rotation script, and `DATA_ENCRYPTION_KEY` validated as 64 hex chars at boot.
- **Identity tokens.** `algorithms: ['RS256']` stated on both verifications
  (#272), issuer and audience pinned, `sub` cross-checked, 12 tests.
- **Sessions.** Stored as `sha256(raw)` only; a database dump yields no bearer.
- **Plaid webhooks.** ES256 JWT + `request_body_sha256` compared with
  `timingSafeEqual`.
- **Transport headers.** HSTS and `X-Content-Type-Options`, without helmet.
- **BOLA.** A systematic cross-tenant sweep (#262).
- **CI scanning.** CodeQL on PRs, Semgrep, Trivy, SBOM, gitleaks including full
  history. **G1.19 is closed**: `security.yml` treats everything outside docs as
  code, so a PR swapping an action for a malicious one faces every scanner, and
  it fails *toward* scanning when the base cannot be trusted. `.trivyignore` is
  gone entirely.
- **Vendor calls.** All 17 clients now have a 5s per-attempt timeout and retry
  (#273), with a grep-based guard so a new bare `fetch` cannot creep back.

### The gaps, in priority order

**1. There is no error tracking of any kind.** No Sentry, Bugsnag, Rollbar or
equivalent, in backend or iOS. `incident-response.md` says it plainly: nothing
alerts, and discovery will realistically come from a user or a researcher. For
testing on your own phone this is the single most valuable addition — a crash or
a 500 on device currently leaves no trace you will find.

**2. No crash reporting on iOS.** G3.10 (MetricKit into `/api/telemetry`) is
unbuilt. Note the audit's own constraint: MetricKit is a system framework, so it
adds no vendor and no `service-providers.md` entry. That makes it the
cheap option, and it is the one the audit recommends.

**3. No uptime monitor** (T3). Five minutes, free, founder task. The audit found
the staging API returning 503 *by accident* because this did not exist.

**4. `last_credit_score` is unencrypted** (G2.10). One column, one hour, and the
audit calls it the single most sensitive scalar in the database.

**5. Crypto downgrade paths** (G2.11): `ALLOW_LEGACY_PLAINTEXT_READS` defaults
true and its own comment says to set it false once the backfill reports zero
rewrites, which has not happened. Two of three `plaid_items` rows on staging
hold **plaintext** access tokens predating migration 0048.
`scripts/backfill-encrypt-pii.ts` exists and has evidently never run. **Must not
be run locally** — it encrypts with whatever key the process holds, and the
local Keychain copy is not known to match the Fly secret.

**6. Database role split** (G2.9): one role does migrations and runtime.

**7. Sign in with Apple nonce** (G1.23 remainder). Deliberately skipped: done
properly it needs single-use server-side storage, not the "two lines each side"
the audit estimates, and it sits on the one flow that must keep working.

### Recommended order for a personal-device test

Error tracking first, because everything else you learn on device depends on
being able to see what broke. Then the uptime monitor. Then `last_credit_score`
encryption before any real credit data flows.

## 3. API expansion: use what we already pay for

The through-line of the whole session, and it kept producing bugs: **what is the
API telling us that we throw away?**

### Closed this session

| PR | Found |
|---|---|
| #274 | Plaid account subtypes stored forever, used only for debts. **A five-year CD counted as emergency cash**, and the creature reacted to it |
| #276 | Zerion's five-way position split (wallet/staked/locked/deposited/borrowed) — we read only the total |
| #277 | Plaid security type and `account_id` dropped; and `refresh.ts` vs `snapshot.ts` were two loops writing one cache payload with different types |
| #279 | **Unpriced assets persisted as $0.** `getSpotPrices` never throws, so one Coinbase outage would have zeroed all sixteen chains |
| #284 | Zerion's `implementations[].address`, `flags.verified`, `is_trash` discarded — plus a third silent-zero site |

### Still discarded, verified today

**HIGH — Plaid holdings: `vested_quantity`, `vested_value`, `tax_lots`.**
Absent from `PlaidHolding` (`plaid/types.ts:141`) entirely. Unvested equity is
**not the user's money yet**, so counting it inflates net worth in the
flattering direction — same defect class as the CD bug. RSUs and ESPP are
20–50% of net worth for the tech workers most likely to be early adopters.
`tax_lots` is also strictly better than the single `cost_basis` scalar for any
gains work. DR-32 flags one cost: `/investments/transactions/get` is **a second
Plaid subscription**, so the contribution-rate half has a price the vesting half
does not.

**MEDIUM — `personal_finance_category.confidence_level`.** Typed at
`plaid/types.ts:7` and read nowhere. Plaid returns `VERY_HIGH` through `LOW`,
and a LOW-confidence category currently drives the spending guardrails with the
same weight as a certain one.

**Confirmed well covered, so nobody re-audits:** Alpaca (`assetClass`,
`costBasisUsd`, `unrealizedPlUsd`, `avgEntryPriceUsd` all captured), Coinbase
(`hold` added after the audit found it), Kraken (tokenized suffixes, five fiats,
real FX), Hyperliquid (spot *and* perps).

**Not exhaustive.** This was a sample of the highest-value vendors, not a
complete field-by-field audit of all 35 integrations. A full sweep comparing
each vendor contract in `docs/context/` against our types is itself a task worth
doing, and it has found something every time it has been run.

### Built but deliberately unwired

**#284's DexScreener client.** Prices tokens Coinbase does not list, and returns
`liquidity.usd` in the same call — the field that separates a real $50,000
holding from one quoting $50,000 in a $500 pool. Zerion now hands over the
contract address, which is the only safe key (symbols are neither unique nor
owned; pricing by ticker lets an impostor token choose the number).

**Nothing is wired into the net-worth figure, on purpose.** Four defensible
options: count at face value, count and flag, exclude from the total and list
separately, discount. **Recommendation:** exclude, using machinery that already
exists — `ClassStatus` has `stale_excluded` and the response carries
`excluded: { count, classes }`, which is precisely "shown honestly, not
counted". And keep it out of the *reactive* signal so the creature never
celebrates a fiction. Antoine's call; same question as lawyer Q5.

## 4. APIs to sign up for, US launch

### Two free keys that switch on whole asset classes

Both integrations are **already built** and throw without a key:

| Key | Free tier | Signup |
|---|---|---|
| `RENTCAST_API_KEY` | 50 calls/month, no card | Self-serve |
| `MARKETCHECK_API_KEY` | 500 calls/month, 5/sec | Self-serve, `developers.marketcheck.com/sign-up` |

Property is the largest asset most Americans own and currently throws on every
call. Two cautions: MarketCheck's next tier is **$299/month** with no middle
step, and **neither benefits from the shared-price cache** (#281) because both
are keyed on something unique — an address, a VIN.

### Free, no signup at all, wiring only

**DexScreener** (done, #284), **NHTSA vPIC** (US VIN decode), **FHFA** house
price index, **UK Land Registry**, **Eurostat** (all 27 EU states in one call).

### Free key, but they need code too

Only worth signing up if the integration is being built — an unused key is a
secret to manage.

- **FRED** — US house price index. Enables the *derived* valuation strategy
  (purchase price + index) that DR-21 already settled as the design and which
  `real_estate_assets` has no columns for. Better than RentCast long-term: no
  per-call ceiling, and it transfers to the UK and EU for free.
- **GoPlus Security** — honeypot and scam-token detection. No spam filter exists
  outside Zerion's own flag.

### Do not sign up

**CoinGecko** and **CoinMarketCap** free tiers are **not licensed for commercial
use**. Anything requiring a sales call. **Akoya** (workplace 401k) is
entity-gated.

### No API exists at any price

Manual entry is the answer, not a vendor hunt: **RSUs/ESPP at the recordkeeper**
(though see §3 — Plaid reaches vesting where the plan is connectable), **life
insurance cash surrender value**, **TreasuryDirect / I-Bonds**.

### Spinwheel is not blocked on code

Sandbox is **free and fully self-serve** at `developer.spinwheel.io`. Production
needs a rep. Terms read 2026-08-19 (#283): **FCRA appears in none of the three
documents**, the Developer Policy makes the developer "solely responsible" for
legal compliance, and the EUA frames the consumer as instructing *the
Application*. The contracts point the duty at Coiny. Ask lawyer Q8 **and**
production pricing in one conversation — nobody publishes it, and it is the only
genuinely unknown cost.
