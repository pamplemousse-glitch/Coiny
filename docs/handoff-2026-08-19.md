## Where to start next session

### 1. Parse the vesting and tax-lot fields (the open thread)

`/investments/holdings/get` returns `vested_quantity`, `vested_value` and
`tax_lots`, and `PlaidHolding` (`plaid/types.ts:141`) carries none of them.

**Why it matters:** unvested equity is not the user's money yet. Counting it
inflates net worth in the flattering direction — the same defect class as the CD
bug in #274. And `tax_lots` is strictly better than the single `cost_basis`
scalar for any future gains work.

Same shape as #274 and #277, so the pattern is established. One cost to weigh,
flagged by DR-32: `/investments/transactions/get` is **a second Plaid
subscription**, so the contribution-rate half has a price the vesting half does
not.

### 2. Decide how a thinly-traded holding should be presented

#284 built the DexScreener client and made Zerion hand over the contract
address, but **nothing is wired into the net-worth number**, on purpose. Four
defensible options: count at face value, count and flag, exclude from the total
and list separately, or discount.

**Recommendation, not yet acted on:** exclude from the total using the machinery
that already exists — `ClassStatus` has `stale_excluded` and the response
carries `excluded: { count, classes }`, which is precisely "shown honestly, not
counted". And keep it out of the *reactive* signal so the creature never
celebrates a fiction.

This changes a user-visible number, so it is Antoine's call, and it is the same
question as lawyer Q5.

### 3. Small, decided, unbuilt

- **`ownership_pct`** on manual and declared assets, default 100. One column,
  one multiply. A jointly-owned house currently counts 100% to whoever entered
  it — a silent overstatement for anyone with a partner. Antoine said "ok".
- **Native currency alongside every USD value.** One column per value table, no
  UI. `prd.md:490`'s anti-corner-painting rules cover *formatting* and are
  followed; the corner is in the schema, where every value column is
  USD-denominated by name. Doing this now means the §30 multi-currency migration
  has real data instead of an impossible backfill.

## Costs, as far as they are known

**To be live: roughly $25-35/month.** Fly (~$5-15), Neon Free until the G4.2
Launch upgrade ($19), Apple $99/yr already paid, domain owned, Plaid **$0** on
the Trial's 10 production Items, RentCast and MarketCheck free tiers.

Two costs scale with users and **both are sales-gated with unpublished pricing**:
Plaid beyond 10 Items (own estimate ~$0.30/user/month) and Spinwheel production.

The structural point worth keeping: **price data is shared, account data is
per-user.** After #281 an extra user in an unsupported country costs
approximately nothing, because they have nothing to link and the price feeds are
cached. The expensive user is the American who links banks and does not convert.
