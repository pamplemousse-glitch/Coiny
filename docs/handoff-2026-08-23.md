## 3. Also waiting on a decision

**Two CodeQL alerts on `main`,** both HIGH, both at `discogs/client.ts:44`:
`js/weak-cryptographic-algorithm` and `js/insufficient-password-hash`. Both are
false positives. The HMAC-SHA1 is the OAuth 1.0a signature method (RFC 5849);
HMAC's security does not rest on collision resistance, so the SHA-1 collision
attacks do not touch it, and NIST still permits HMAC-SHA-1 for authentication.
No password is hashed anywhere near that line.

They are not in the required-check set, so they do not block merges, but two
permanently-red HIGH alerts train everyone to ignore CodeQL, which is the
muted-alarm failure this whole programme is about. Dismiss both in the Security
tab with that reasoning, or ask an agent for a narrow per-file config exclusion.
There is no `.github/codeql/` config today, only `queries: security-and-quality`.

written permission, and whether to apply to Akoya / Empower / Carta.

## 4. What landed, and the two ideas worth keeping

Thirteen PRs, #308 to #320. `docs/connection-resilience-survey.md` is the
research they implement; its section 5 carries the agreed order and its gap
list is annotated with what closed.

### The survey's own two findings

**Schema validation is the wrong instrument for drift.** Mapped onto the five
data-observability pillars, #302 (Polkadot) violated *distribution* and #295
(Zerion pagination) violated *volume*. Neither touched *schema*. A Zod schema
catches the one pillar that did not break. That is why #316 checks plausibility
against the previous value instead of adding stricter parsing.

**The circuit breaker was keyed on the wrong axis.** Envoy ejects per upstream
HOST with `consecutive_5xx` defaulting to 5; ours is per (user, class) with a
threshold of 5. Same number, inverted axis. The consequence that matters is not
cost: at roughly one sample per refresh interval a RATE cannot be computed at
all, so re-keying is a precondition for every other improvement rather than one
of them. #313 proved the fix shape with a token bucket, which works at low
volume precisely because it carries state instead of sampling.

### Two patterns that paid off repeatedly

**A control that is present in source and absent in effect.** #311 disabled
Sentry integrations by name and two of five names were wrong, so those filters
did nothing, while a third disabled `Http` when every vendor client uses
`fetch`. #312 fixed it, and the durable fix is a test asserting every name
exists in the SDK, not the corrected names.

**Two copies of one rule will drift.** #309 was the backend and iOS disagreeing
about whether `reauth_required` counts toward the total. The fix was not
resyncing them; it was deleting the client's copy and reading the server's
`excluded` list. `connection-health.ts` stores no `status` for the same reason.

### What is measurably better

- pino redaction reached **two levels** of nesting, not "any". Measured:
  `{a:{b:{c:{email}}}}` leaked. Now depth-unbounded at a cost of 1.29µs/line
- Retries had no jitter and no budget. Now AWS full jitter plus gRFC A6 token
  throttling, keyed per vendor
- All 13 connection tables record health, and a user is told WHICH wallet broke,
  with a Reconnect button only when they are the one who can fix it

## 6. Limits that no amount of further work removes

Stated so nobody re-derives them.

**Fly log retention.** Ordinary request logs age out and nothing ships them
anywhere. `ops_events` covers vendor failures for 90 days; nothing covers the
rest. `launch-gap-analysis.md` section 9 named this as the real weakness of
staying first-party, and adopting Sentry did not fix it: Sentry catches
exceptions, not the absence of them. Closing it needs a destination and a
decision.

**iOS has no crash reporting.** G3.10 (MetricKit) is unbuilt. An agent can
build it; the App Store privacy label needs founder approval first.

**Invariants cannot distinguish "the user sold" from "the vendor broke"** at one
user. Only breadth across many accounts separates them. That is why #316 alerts
rather than blocks, and it is a ceiling rather than a bug.

**The survey's competitor-UX section is thin.** Monarch's help centre 403s
behind Cloudflare to both WebFetch and curl. Ten minutes of screenshots from
someone with the apps installed beats anything an agent can fetch.

## 7. Standing instructions

Unchanged from `handoff-2026-08-21.md` section 5, plus two learned today.

- Push and open a PR for validated work without asking; auto-merge on green CI
- One logical chunk per PR
- **Run all three CI steps after the LAST edit**: `lint`, `typecheck`,
  `test:coverage`
- **Reproduce a CI failure at FULL parallelism before diagnosing it.**
  `--maxWorkers=3` is the documented mitigation for the PGlite hook timeouts in
  `compression`, `health-liveness`, `migration-journal` and `scheduler`, and it
  also MASKS real timing-dependent failures. One was masked today: a test
  attached a rejection handler after advancing fake timers, and CI failed the
  run on an Unhandled Rejection while reporting all 153 files passed.
- **A CI `test` failure with every file passing is not a test failure.** It is
  an unhandled rejection or an open handle. Read the failure text, not the pass
  counts.
- **Do not assert that the rest of a document is correct unless you have just
  checked the rest of the document.** `environments-setup.md` rotted for eight
  days behind exactly that sentence (#317).
- Never read or echo Keychain values
- Before saying something does not exist: `prd.md`'s DR register, then
  `docs/context/`, then the vendor's own page, then the actual file
